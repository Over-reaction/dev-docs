# 通用工程结构标准

## 文档版本

| 版本号 | 修订时间   | 修订者 | 备注 |
| ------ | ---------- | ------ | ---- |
| V1.0.0 | 2026/11/12 | 宁海   | 统一三类项目的基础工程要求 |

## 适用范围

适用于 Java 单体、微服务和客户端项目。具体目录结构分别见[单体项目结构标准](/backend/other/monolith-project-structure)、[微服务项目结构标准](/backend/other/microservice-project-structure)和[客户端项目结构标准](/backend/other/client-project-structure)。

## 目录与命名规范

1. 项目使用统一根包。Java 包名使用全小写英文，类名使用大驼峰，Maven 模块名使用小写英文和短横线。
2. 业务代码按业务模块组织，只创建实际使用的目录，不得为补齐目录创建空类。
3. 对象名称体现用途，`DO`、`DTO`、`VO` 等后缀在项目内保持一致。

### 公共代码归属

- `common/` 只存放通用响应、基础异常、注解和工具类等公共基础代码，不得依赖业务模块。
- 具体业务逻辑留在所属模块；工具类按用途命名，不得堆积无关功能。

### 通用分层职责

| 目录或包 | 职责 |
| --- | --- |
| `config` | 配置加载、校验与组件装配 |
| `controller`（HTTP） | 接收请求、参数校验、权限声明和返回响应 |
| `service`、`service.impl` | 业务接口与实现，负责业务处理和事务编排 |
| `manager` | 按需处理缓存、组合查询、批量调用和结果组合，外部请求通过 `client` 发起 |
| `mapper`、`repository` | 数据查询与存储 |
| `entity`、`dto`、`vo` | 分别存放持久化、传输和展示对象 |
| `enums` | 当前业务模块的枚举 |
| `converter` | 对象转换，不执行查询或业务流程 |
| `client` | 封装外部接口的协议、认证和请求，不承担业务组合逻辑 |
| `job`、`listener` | 调度或事件入口，调用业务服务 |

## 通用调用约束

1. 交互入口调用业务服务，不得直接访问数据库或外部 SDK；业务服务不得依赖界面组件。
2. 各层和模块单向依赖，不得形成循环依赖或直接访问其他模块的私有实现。
3. 本地事务由业务服务统一编排；持久化对象不得直接作为对外接口入参或响应。
4. 异常处理与日志记录遵守[异常日志规范](/backend/standards/exception-logging)，不得重复记录同一异常。

## Maven 模块与构建

1. 父 POM 统一管理版本与插件，子模块只引入实际需要的依赖。`dependencyManagement` 管理版本，`dependencies` 声明依赖。
2. 应用打包插件由父 POM 的 `pluginManagement` 管理，启动模块在 `build/plugins` 中显式启用；业务库、公共库和接口库生成普通 JAR，不执行 Spring Boot 的 `repackage`。
3. 依赖新增或升级时检查版本冲突与兼容性；正式发布不得使用 `SNAPSHOT` 依赖或覆盖已有正式制品。

## 配置管理

1. 默认配置与环境配置分开，配置优先级明确；地址、路径和任务参数通过配置提供，不得硬编码开发环境信息。
2. 部署账号、密码和密钥通过受控配置提供；运行时令牌按认证流程获取并受控保存。敏感信息不得写入源码、打包默认配置、日志或版本库。
3. 首次配置加载校验失败时，明确报错并停止启动；动态配置更新失败时，保留原配置并报告原因，涉及组件重启时明确生效步骤。

## 源码、测试与资源管理

1. 生产代码与资源放在 `src/main/`，测试放在 `src/test/`，测试包结构与生产代码对应，测试配置和数据与生产隔离。
2. 打包资源只读，日志、上传文件、本地数据库等运行数据写入外部可配置目录，不得写回 JAR 或 classpath。
3. 程序文件、业务数据、缓存和临时文件分开管理；日志和临时文件设置容量与清理规则，数据目录对运行账号可写。

## 外部调用与后台任务

1. 外部调用统一封装，设置认证、超时和错误处理；重试设置上限，并处理重复执行问题。
2. 线程池和任务队列设置容量上限，任务具备明确的状态、取消和超时处理方式。
3. 应用退出时停止接收新任务，处理在途任务，并关闭线程池、连接和外部资源。

## 工程辅助目录

| 目录或文件 | 内容要求 |
| --- | --- |
| `db/` | 初始化与升级脚本；升级脚本按版本归档，已执行的脚本不得覆盖修改 |
| `deploy/`、`scripts/` | 实际支持环境的部署、构建和诊断脚本 |
| `docs/` | 架构、接口与部署说明 |
| `README.md` | 运行环境、构建启动步骤、配置来源及数据与日志位置 |

使用数据库迁移工具时，脚本放在配置的扫描目录，不得重复维护两套升级脚本。

## 版本库与交付管理

1. 构建产物、日志、运行数据、缓存、下载的模型和更新包不得提交版本库；允许提交脱敏配置模板、升级脚本和必要的测试样本。
2. 发布产物记录版本和来源，部署说明写清环境依赖、配置、启动、验证与回滚步骤；客户端补充安装、卸载与数据保留规则。
3. 接口遵守[接口文档标准](/backend/other/api-standard)和[接口权限标准](/backend/other/api-permission-design)。
