# 接口权限设计规范

## 文档版本

| 版本号 | 修订时间   | 修订者 | 备注 |
| ------ | ---------- | ------ | ---- |
| V1.0.0 | 2026/11/09 | 宁海   | 初稿 |

## 一、适用范围

适用于系统菜单、功能按钮、后端 API、公共接口及角色授权管理。权限控制以**后端实际校验**为准，前端菜单及按钮权限仅用于界面展示和操作入口控制。

## 二、权限控制原则

1. **菜单权限与接口权限分离**：菜单可见不代表拥有全部接口操作权限；接口复用也不应自动授予其他菜单的访问或操作权限。
2. **业务操作独立授权**：新增、修改、删除、审批、导出等操作按所属业务分别定义权限字符。
3. **公共查询按需鉴权**：低风险共享查询可采用登录认证及数据范围控制；敏感查询必须增加相应权限校验。
4. **动态业务权限校验**：复用接口涉及多个业务对象时，按实际操作对象判断所需权限，不能仅凭拥有任意一个菜单权限就放行。
5. **数据权限独立校验**：具有功能权限不代表可以访问所有项目、部门或业务记录。
6. **最小权限原则**：角色只获得完成工作所需的权限，公共接口不得成为绕过业务授权的入口。

## 三、接口分类与权限要求

| 接口类型         | 权限要求                                                     | 示例                       |
| ---------------- | ------------------------------------------------------------ | -------------------------- |
| 页面专属接口     | 采用对应业务的独立权限字符，必要时叠加数据权限               | `project:requirement:edit` |
| 业务公共查询接口 | 登录认证 + 数据范围控制；涉及敏感数据时增加功能权限          | 查询可选人员、项目选择     |
| 业务公共操作接口 | 根据实际业务类型及资源归属校验对应操作权限                   | 统一任务处理、统一审批     |
| 基础服务接口     | 根据风险使用登录认证、独立功能权限或专门安全校验             | 文件上传、验证码、文件下载 |
| 系统集成接口     | 根据调用方采用签名、密钥、身份认证等校验，并校验业务操作权限 | 企业微信回调、数据同步     |

## 四、权限字符定义

1. 业务操作权限字符采用 `模块:资源:操作` 格式，例如 `project:bug:edit`、`project:requirement:approve`。
2. 不同业务的敏感操作不得因共用一个 API 而直接共用权限字符。
3. 公共查询接口若无需单独的功能权限字符，文档须标注“无”，并说明登录认证及数据范围要求。
4. 同一权限字符只能表示同一项明确的授权能力，避免将无关菜单按钮配置为同一个权限字符。
5. 多种权限条件应说明是“全部满足”还是“任意满足”，以及判断所依据的实际业务对象。

## 五、公共接口复用规则

**场景：** 需求管理和 BUG 管理均调用“查询可选人员”接口。

- 可以共用接口及其查询实现，但不需要让两个菜单共用同一个业务按钮权限。
- 如果接口仅返回允许访问的低敏感人员信息，可以采用登录认证 + 数据范围控制。
- 如果涉及敏感信息，需增加独立权限或按业务场景校验。

**场景：** 需求处理和 BUG 处理共用一个提交接口。

- 处理需求时校验 `project:requirement:handle`。
- 处理 BUG 时校验 `project:bug:handle`。
- 服务端应根据数据库中的实际记录类型及资源归属判断权限，不能仅信任前端提交的业务类型。
- 禁止仅使用“拥有上述任一权限”作为处理全部业务对象的放行条件。

## 六、接口文档标注要求

所有接口在 Apifox 中必须填写以下权限信息，不得留空：

| 字段         | 填写要求                                               |
| ------------ | ------------------------------------------------------ |
| 接口权限字符 | 填写实际权限字符；无单独权限字符则填写“无”             |
| 权限校验方式 | 公开访问、登录认证、功能权限、动态业务权限、签名校验等 |
| 数据权限     | 说明项目、部门、人员或记录级数据范围；不适用则写“无”   |
| 特殊说明     | 多权限逻辑、调用场景、特殊限制（如适用）               |

> 例：查询可选人员；接口权限字符：无；权限校验方式：登录认证；数据权限：当前用户可访问的组织/人员范围。

“权限字符：无”**不等于公开访问**。公开接口、登录后接口与使用功能权限字符的接口应明确区分。

## 七、检查与维护

1. 前端菜单和按钮权限仅控制可见性，后端必须独立执行鉴权。
2. 新增或修改接口时，必须同步检查并更新 Apifox 中的权限说明。
3. 涉及公共接口权限变更时，须评估所有调用场景和角色影响。
4. 以下情况判定为不合格：权限字符缺失或与代码不一致；跨业务误用权限字符；敏感操作仅验证登录；绕过数据权限；公共操作接口错误使用任意权限放行全部业务对象。
