## 一、使用说明

1. 统一使用 **Apifox** 管理接口文档。
2. IDEA 使用 **ApifoxHelper** 插件上传、更新接口；上传后检查目录和字段信息。
3. 接口新增或变更后，**前后端联调前**必须同步 Apifox；提交测试前确保文档与代码一致。

## 二、结构标准

### 1. 目录结构

> 接口注释中使用/分层。例如：基础服务/文件管理

按照 **项目 → 模块 → 目录 → 接口** 组织：

- **项目**：一个系统或独立 API 管理项目。
- **模块**：优先对应后端服务或独立业务；单服务项目可使用默认模块。
- **目录**：对应稳定的业务模块、菜单功能或公共能力。
- **接口**：具体 API 定义。

以下“项目：”“模块：”“目录：”仅用于说明，实际命名无需添加这些前缀。

```text
项目：管理系统
├── 模块：项目管理服务
│   ├── 目录：项目管理
│   │   ├── GET  查询项目列表
│   │   └── POST 新增项目
│   ├── 目录：需求管理
│   ├── 目录：任务管理
│   ├── 目录：BUG管理
│   └── 目录：业务公共接口
│       └── GET 查询可选项目
├── 模块：系统管理服务
│   ├── 目录：用户管理
│   ├── 目录：角色管理
│   ├── 目录：部门管理
│   └── 目录：业务公共接口
│       └── GET 查询可选人员
└── 模块：基础服务
    ├── 目录：文件管理
    ├── 目录：认证管理
    └── 目录：系统集成
        └── 目录：微信集成
```

### 2. 模块及目录规则

1. **模块归属**：优先按后端服务划分，不要求与前端菜单一一对应；同一服务原则上放在同一模块。
2. **禁止无目录接口**：所有接口必须放在明确目录下，禁止直接放在模块根目录。
3. **业务归属优先**：有明确归属的接口放在所属业务目录，不能因为其他页面调用就迁入公共目录。
4. **接口唯一归属**：同一实际接口只维护一份正式定义；同一服务内相同请求方式与完整路径原则上不得重复定义。
5. **目录命名**：禁止长期使用“其他”“临时接口”“未分类”等无明确含义的目录。
6. **控制层级**：模块下的目录原则上不超过三级；不必与前端菜单完全一致。
7. **非页面接口**：定时任务触发接口、第三方回调等归属对应业务或系统集成目录。

### 3. 接口分类标准

| 分类         | 定义                                 | 示例                                     | 推荐归属                                             |
| ------------ | ------------------------------------ | ---------------------------------------- | ---------------------------------------------------- |
| 页面专属接口 | 主要服务于某个业务页面或功能         | 查询需求详情、修改 BUG 状态、新增任务    | 对应业务目录                                         |
| 业务公共接口 | 为多个业务场景提供明确的共享业务能力 | 人员选择、项目选择、组织机构树、审批记录 | 优先业务归属目录；无单一业务归属时放业务公共接口目录 |
| 基础服务接口 | 与具体业务无关的通用技术能力         | 文件上传、下载、图片预览、认证、验证码   | 基础服务模块下对应目录                               |
| 系统集成接口 | 与其他系统或第三方平台交互           | 企业微信回调、外部数据同步               | 对应业务或系统集成目录                               |

**复用规则**：其他页面直接调用原接口，不重复创建；公共接口应明确维护责任人，不兼容变更前须评估调用方影响。

## 三、接口定义标准

每个正式接口必须包含以下信息：

| 内容                     | 规范要求                                                                       |
| ------------------------ | ------------------------------------------------------------------------------ |
| 接口名称                 | 使用“操作 + 业务对象”，如“查询需求详情”                                        |
| 请求方式与路径           | GET、POST、PUT、DELETE 等及完整路径，与代码一致                                |
| 接口描述                 | 说明接口用途及必要业务规则                                                     |
| **接口权限字符（必填）** | **每个接口必须明确标注实际权限标识；无权限字符的必须写明“无”，并说明访问限制** |
| 请求参数                 | 字段名称、类型、是否必填、说明及必要约束                                       |
| 响应参数                 | 字段名称、类型、含义及嵌套结构                                                 |
| 请求与成功响应示例       | 提供与实际接口结构一致的有效示例                                               |
| 异常响应                 | 说明主要业务错误码及失败原因；通用错误可引用统一定义                           |

### 接口权限字符标注要求

1. 在 **Apifox 接口描述**中固定标注 `权限字符：xxx`，不得留空或只写“见代码”。
2. 权限字符必须与后端实际权限校验一致，例如 `project:requirement:list`；存在多个权限字符时全部列出，并说明“满足任一项”或“必须全部满足”。
3. 无权限字符时，统一写 `接口权限字符：无`，并进一步注明 `访问限制：公开访问 / 登录即可访问 / 内部调用 / 第三方验签` 等实际方式。
4. 调整权限校验逻辑或权限字符时，必须同步更新 Apifox 文档。

**示例：**

```text
接口名称：查询需求列表
请求方式：GET
请求路径：/api/requirements
接口权限字符：project:requirement:list
访问限制：登录并具有上述权限
```

```text
接口名称：企业微信消息回调
请求方式：POST
请求路径：/api/wecom/callback
接口权限字符：无
访问限制：第三方签名校验
```

> 所有接口必须明确标注接口权限字符及权限校验方式，具体规则参见《接口权限设计规范》。

## 四、维护与检查要求

1. **同步时点**：联调前完成接口文档更新；提测前再次核对代码和文档。
2. **变更管理**：请求参数、响应结构、接口路径、权限字符变更时必须同步更新；废弃接口标记废弃并注明替代接口（如有）。
3. **质量检查**：接口目录归属、文档完整性、代码一致性及权限字符标注均纳入检查。

| 检查项     | 不合格判定                                                   |
| ---------- | ------------------------------------------------------------ |
| 目录归属   | 接口位于模块根目录，或归属明显不符                           |
| 接口重复   | 同一实际接口存在多份正式定义                                 |
| 参数与示例 | 关键参数、响应字段缺失说明，或示例与实际结构不符             |
| 权限字符   | 未标注、标注错误、与代码不一致，或无权限字符却未注明访问限制 |
| 文档同步   | 联调或提测时文档与实际代码不一致                             |
| 废弃状态   | 已废弃接口未标记                                             |
