# 前端开发标准

## 1. 文档说明

### 1.1 编写目的

为统一前端开发标准，规范团队代码编写方式，提高代码质量、可读性、可维护性及团队协作效率，特制定本标准。

本标准作为前端开发、代码审查及项目质量检查的参考依据。

### 1.2 适用范围

本标准适用于公司前端研发团队开发及维护的相关项目，包括但不限于：

- PC Web 管理系统
- H5 页面
- 微信小程序
- 其他前端相关项目

不同技术栈的项目，应遵循对应技术规范；通用规范适用于所有前端项目。

### 1.3 执行要求

- 新开发的项目及功能原则上应遵循本标准。
- 已有项目在维护、重构时逐步向本标准靠拢。
- 特殊业务场景无法遵循标准时，应在技术方案或代码审查中说明原因。
- 本标准未明确规定的内容，可参考项目现有规范及相关技术官方文档。

## 3. 单条规约格式说明

按约束力从强到弱，规约分为强制、推荐和参考三个级别。

- **【强制】** 必须遵守。违反这类规约可能引起严重后果。
- **【推荐】** 尽量遵守。长期遵守这类规约有助于提高系统稳定性和协作效率。
- **【参考】** 充分理解。用于引导技术实践，为个人学习、团队沟通和项目协作提供参考。

每条规约在描述开头标注级别。以下是一条强制规约的写法。

> **【强制】** 使用 2 个空格缩进。

### 规约编号

规约编号放在正文末尾，格式为 `领域-标准-级别-主题-序号`，各段用连字符 `-` 连接。

编写 Markdown 时，在规约正文末尾加一个空格，再写 `[FE-VUE3-M-COMPONENT_NAME-001]`。

- **领域**使用 `FE`（Frontend，前端）或 `BE`（Backend，后端）。
- **标准**使用标准代号，例如 `VUE3` 表示 Vue 3 开发标准，`JAVA` 表示后端 Java 开发标准。
- **级别**使用 `M`（Must，强制）、`S`（Should，推荐）或 `R`（Reference，参考）。
- **主题**使用简短的大写英文代号，多个单词之间用下划线 `_` 分隔，例如 `COMPONENT_NAME` 表示组件命名。
- **序号**使用三位数字。领域、标准和主题相同的规约共用一组序号，从 `001` 起依次分配。

规约移到其他章节时沿用编号。规约级别变更时，只更新级别字母。

- `FE-VUE3-M-COMPONENT_NAME-001` 表示前端 Vue 3 标准组件命名主题的第 1 条规约，级别为强制。
- `BE-JAVA-M-NAME-001` 表示后端 Java 标准命名主题的第 1 条规约，级别为强制。

## 4. 维护说明

- 本标准由前端研发团队统一维护。
- 规范调整应经过团队讨论或技术评审后实施。
- 每次正式发布规范变更时，应同步更新版本号及修订记录。
