# 功能：合同管理-合同列表-新增/编辑合同-合同方更新方案

> 功能命名规范：`${一级菜单}-${二级菜单}-...-${功能名称}`

## 1. 功能说明

合同新增、编辑时，支持合同方及联系人信息的新增、修改、删除。

## 2. 输入条件

说明页面接收的参数、关键数据字段及数据格式。

| 字段            | 说明                                           |
| --------------- | ---------------------------------------------- |
| contractRowId   | 合同 ID，编辑时使用                            |
| partyType       | 区分甲、乙、丙、丁、其他方                     |
| groupId         | 区分不同合同方；同一方下的主体使用相同 groupId |
| partySort       | 不同合同方的排序顺序                           |
| entitySort      | 同一方下主体的排序顺序                         |
| partyName       | 合同方标题                                     |
| partyEntityName | 合同主体名称                                   |
| contactList     | 对应合同主体的联系人数组                       |

**JSON 示例：**

```json
[
  {
    "partyType": "乙",
    "groupId": "2",
    "partySort": "2",
    "partyName": "乙方",
    "partyEntityName": "测试乙方合同方",
    "entitySort": "1",
    "contactList": [
      {
        "contactName": "测试联系人",
        "contactPhone": "13888888888"
      }
    ]
  }
]
```

## 3. 交互设计（按需）

说明用户操作流程、页面交互规则及状态变化

1. 点击“新增合同方”，动态增加合同方表单。
2. 点击“新增主体”，在当前合同方下增加主体信息。
3. 点击“新增联系人”，在对应主体下增加联系人信息。
4. 删除合同方时，同步移除其下的主体及联系人。
5. 点击“提交”时，对校验失败的字段展示错误提示。

## 4. 处理规则

**重点说明该功能的实现逻辑，包括数据处理、业务校验、接口调用及必要的技术实现方式。**

1. 页面初始化时，编辑模式调用合同详情接口获取数据并回显。
2. 使用 `groupId` 识别同一合同方下的多个主体。
3. 使用 `partySort`、`entitySort` 维护合同方和主体顺序。
4. 根据暂存、提交操作执行对应的表单校验规则。
5. 校验通过后，整理合同主体及联系人数据，调用相应接口。
6. 请求期间设置提交中状态，避免重复提交。

## 5. 技术难点及解决方案（按需）

仅记录实际存在的关键技术难点及对应解决方案，无明显难点时可省略。

| 技术难点               | 解决方案                                 |
| ---------------------- | ---------------------------------------- |
| 多层动态表单的数据管理 | 使用统一数据结构维护合同方、主体及联系人 |
| 动态表单校验           | 根据暂存、提交等操作类型执行不同校验规则 |
| 合同方与主体的关联     | 使用 `groupId` 关联同一方下的多个主体    |
| 动态数据排序           | 统一维护 `partySort`、`entitySort`       |

## 6. 输出结果

说明功能完成后的页面反馈及接口响应处理。

**JSON 示例：**

```json
{
  "msg": "操作成功",
  "code": 200,
  "data": {
    "valid": true,
    "missingPartyList": []
  }
}
```

- 操作成功：提示成功并执行后续页面操作。
- 操作失败：展示接口返回的错误信息。
- 校验失败：提示对应字段或合同方缺失信息。

## 7. 异常处理

1. 接口请求失败时，提示错误并保留当前表单数据。
2. 表单校验失败时，阻止提交并展示具体错误。
3. 请求期间防止重复点击导致重复提交。
4. 不编写无业务依据的过度兼容或多层兜底逻辑。

## 8. 影响范围（按需）

| 影响模块 | 说明                     |
| -------- | ------------------------ |
| 合同新增 | 合同方信息录入           |
| 合同编辑 | 合同方信息回显及修改     |
| 合同详情 | 合同方信息展示（如涉及） |
